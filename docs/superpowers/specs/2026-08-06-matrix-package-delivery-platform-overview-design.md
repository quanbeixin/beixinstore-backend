# 矩阵包投放平台概览设计

## 1. 目标

矩阵包当前使用包级别的投放平台、投放渠道和投放状态，无法表达不同平台各自的渠道和状态。本次将其替换为按平台维护的投放平台概览。

每个矩阵包最多维护 Meta、Google、Snapchat、TT 四个平台，每个平台独立记录：

- 投放渠道：自投、代理
- 平台状态：在投、待投、停投、封禁
- 最近修改人
- 最近修改时间

## 2. 数据模型

新增 `matrix_package_delivery_platforms` 明细表，一条记录代表一个矩阵包下的一个投放平台。

核心字段：

- `package_id`
- `platform_code`
- `channel_code`
- `status_code`
- `created_by`
- `updated_by`
- `created_at`
- `updated_at`

`package_id + platform_code` 建立唯一约束，防止同一矩阵包重复配置同一平台。

平台、渠道和状态继续由系统字典提供。投放状态字典补充：

- `PENDING`：待投
- `BANNED`：封禁

## 3. 后端接口

新增矩阵包子资源接口：

- `GET /api/matrix-packages/:id/delivery-platforms`：查看平台概览
- `PUT /api/matrix-packages/:id/delivery-platforms`：整体保存平台概览

保存接口接收平台数组，后端在事务内校验并替换当前配置。校验规则：

- 仅运营中矩阵包允许保存
- 平台编码不可重复
- 平台、渠道、状态必须来自启用中的系统字典
- 每条配置必须同时填写平台、渠道和状态

矩阵包列表和详情返回 `delivery_platform_overview`，用于概览展示。列表筛选改为基于明细表的 `platform_code`、`channel_code`、`platform_status_code`。

## 4. 前端交互

矩阵包全景图移除原投放平台、投放渠道、投放状态三列，新增“投放平台概览”列。

运营中矩阵包：

- 概览区展示已配置的平台状态标签
- “编辑”按钮打开可编辑弹窗
- “查看详情”按钮打开只读弹窗

非运营中矩阵包：

- 概览展示 `-`
- “编辑”按钮禁用
- “查看详情”仍可查看历史配置

编辑弹窗按行维护平台、投放渠道和平台状态。平台不可重复，可新增、删除和修改。

详情弹窗固定展示四个平台，未配置的平台显示 `-`。表格列为：

- 投放平台
- 投放渠道
- 当前状态
- 最近修改人
- 最近修改时间

## 5. 历史迁移

迁移现有 `matrix_packages.platform`：

- 将逗号分隔的平台拆分为明细记录
- 每个平台继承旧 `delivery_channel_code`
- 每个平台继承旧 `delivery_status_code`
- 缺少渠道或状态的历史记录不强行生成不完整明细

旧字段暂时保留用于回滚和兼容，但页面、筛选和新保存接口不再读取或写入旧字段。

## 6. 兼容性

开放矩阵包信息接口新增结构化的 `delivery_platform_overview`。旧的 `delivery_platform`、`delivery_channel`、`delivery_status` 暂时保留，避免已有外部调用立即中断，并标记为兼容字段。

生产线快速编辑不再携带旧投放字段，避免修改矩阵包状态时覆盖平台概览。

## 7. 验收

- 运营中矩阵包可以配置多个不同平台及其渠道、状态
- 同一平台不能重复
- 非运营中矩阵包不能编辑平台概览
- 列表概览、详情和筛选均使用新明细数据
- 详情展示四个平台以及最近修改人、最近修改时间
- 历史完整配置可以正确迁移
- 修改矩阵包其他基础信息不会覆盖平台概览
