# APP 版本发布分组聚合设计文档

## 1. 背景与目标

当前 APP 版本发布页面的分组能力是固定的，只支持 `开发者 -> APP -> 发版进度` 这一种树形结构。  
用户希望把分组维度改成可自由组合，并且分组后每条发版记录仍然展示与明细列表一致的完整字段。

目标：

- 支持按多个维度自由组合分组
- 分组顺序由用户决定
- 分组维度扩展到：开发者、APP、发版进度、公司主体、负责人、紧急程度
- 分组后的叶子记录展示完整明细字段
- 不破坏原有明细列表能力

## 2. 范围与边界

### 2.1 In Scope

- 分组维度可配置、可排序、可组合
- 后端按配置动态生成分组树
- 前端支持切换明细 / 分组视图
- 分组视图中叶子记录展示与明细表一致的全部字段

### 2.2 Out of Scope

- 不改发版记录数据模型
- 不新增新的业务字段
- 不做复杂拖拽式分组编辑器
- 不改已有列表筛选逻辑的语义

## 3. 分组维度定义

支持的分组维度如下：

- `developer`：开发者
- `app`：APP
- `status`：发版进度
- `company_subject`：公司主体
- `owner`：负责人
- `urgency`：紧急程度

每个维度的展示名称与取值规则：

- `developer`：优先展示 `app_developer`，为空时显示 `未设置开发者`
- `app`：优先展示 `app_name`，为空时显示 `未设置APP`
- `status`：使用 `release_status_name` 和状态颜色
- `company_subject`：优先展示 `app_company_subject`，为空时显示 `未设置公司主体`
- `owner`：优先展示 `owner_name`，为空时显示 `未设置负责人`
- `urgency`：使用 `urgency_name` 和颜色

## 4. 交互设计

### 4.1 视图切换

页面保留两个视图：

- 明细
- 分组

### 4.2 分组配置

分组视图上方增加分组配置区：

- 可选择 1 到 N 个维度
- 维度顺序即分组层级顺序
- 已选择的维度不可重复
- 可提供常用预设，但最终以当前选择为准

示例：

- 开发者 -> 发版进度
- 开发者 -> APP
- 开发者 -> 发版进度 -> APP
- 公司主体 -> 负责人 -> 紧急程度

### 4.3 分组展示规则

- 中间层节点只展示汇总信息
- 最末层叶子节点展示完整发版记录
- 叶子节点字段与明细列表保持一致
- 默认支持展开 / 收起

## 5. 数据结构设计

### 5.1 明细数据

发版记录基础字段继续沿用现有结构，不新增主表字段。

### 5.2 分组树节点

后端返回树节点统一结构：

- `key`
- `row_type`
- `group_name`
- `group_field`
- `group_value`
- `release_count`
- `children`

叶子节点直接沿用 release 记录字段，并额外带：

- `row_type = release`
- `group_name`
- `release_count = 1`

## 6. 分组算法

### 6.1 原则

- 以用户选择的分组维度数组作为唯一输入
- 按数组顺序递归分组
- 同一条记录按所选维度依次落入树中

### 6.2 分组键规则

每个维度都有自己的标准化取值：

- 空值统一归到对应的“未设置”分组
- 文本统一 trim
- 不改变原始记录值

### 6.3 叶子记录规则

当维度数组耗尽时，输出完整发版记录。

叶子记录必须保留：

- 申请ID
- 版本号
- 发版类型
- 紧急程度
- APP名称
- 开发者账号
- 公司主体
- APP后台地址
- 发版进度
- 前序发版
- 送审预期
- 送审日期
- 上架日期
- 关联需求
- 申请信息
- 发版负责人
- 备注 / 操作信息

## 7. 后端接口设计

### 7.1 列表接口

明细列表保持不变。

### 7.2 分组接口

在现有分组接口上增加分组维度参数：

- `group_by[]=developer`
- `group_by[]=status`
- `group_by[]=app`

若未传 `group_by`，默认兼容旧行为：

- `developer -> app -> status`

### 7.3 校验规则

- 不允许重复维度
- 不允许传入未知维度
- 空数组视为使用默认分组

## 8. 前端页面设计

### 8.1 分组配置区

建议放在分组视图顶部，采用多选下拉或可排序标签式配置。

需要满足：

- 选择维度
- 调整顺序
- 清空重置

### 8.2 表格展示

分组树表格仍使用当前树表能力，但列结构调整为：

- 分组节点：显示汇总信息
- 叶子节点：显示完整明细列

### 8.3 明细一致性

分组视图中的 release 行必须与明细视图使用同一套列定义和渲染规则，避免两套展示口径不一致。

## 9. 兼容性与迁移

- 不影响现有明细列表
- 不影响新增 / 编辑 / 删除流程
- 不传分组配置时保持旧分组结果
- 现有前端默认进入分组视图时可继续使用旧默认组合，避免一次性改变用户习惯

## 10. 测试与验收

### 10.1 功能验收

- 可自由组合分组维度
- 可按不同顺序生成不同树
- 叶子记录展示完整字段
- 明细视图不受影响

### 10.2 边界验收

- 空值能正确归类
- 重复维度会被拦截
- 未知维度会被拦截
- 默认分组兼容旧行为

### 10.3 回归关注点

- 列表筛选结果与分组结果一致
- 分组视图翻页 / 刷新逻辑不回退
- 备注、编辑、删除操作仍只对发版记录生效

## 11. 后续扩展

- 支持记住用户上一次分组配置
- 支持常用分组预设
- 支持导出当前分组结果
- 支持更多分组维度扩展
