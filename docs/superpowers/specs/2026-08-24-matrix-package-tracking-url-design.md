# 矩阵包埋点地址设计

## 目标

在冷备包生产详情的前端补充信息中新增两个字段：

- `prodTrackingUrl`：生产环境埋点地址
- `testTrackingUrl`：测试环境埋点地址

两个字段提供规则生成的默认值，也允许页面人工编辑和开放接口写入。开放矩阵包查询接口返回最终生效值。

## 生成规则

域名前缀沿用 H5 地址的包名归一化规则：包名去除空白、转小写，仅保留字母、数字和连字符。域名沿用现有域名归一化规则，取 `domain_info` 中第一个有效域名并去除协议、路径和首尾点号。

- 生产环境：`https://[域名前缀].data.app.[域名]`
- 测试环境：`https://[域名前缀].test-data.app.[域名]`

例如 Vimi（包名 `Vimi`、域名 `vimi.art`）：

- `https://vimi.data.app.vimi.art`
- `https://vimi.test-data.app.vimi.art`

包名或域名不足时不生成地址，字段显示为空。

## 值优先级

字段采用“持久化覆盖值优先、动态生成值兜底”的策略：

1. 前端补充信息中存在非空人工或接口写入值时，使用该值。
2. 持久化值不存在或为空字符串时，使用当前包名和域名动态生成。
3. 页面清空字段并保存，表示删除覆盖值，随后恢复显示动态生成值。

生成值不写死到数据库，因此在没有覆盖值时，包名或域名变化会自动反映到地址上。

## 页面交互

两个字段放在冷备包生产详情的“前端补充信息”中，位置与 H5 生产、测试环境字段对应：生产地址位于生产环境信息，测试地址位于测试环境信息。

输入框允许人工编辑和清空。初次加载时展示最终生效值。为了区分“生成值”和“覆盖值”，页面提交前将输入值与当前动态生成值比较：相同时持久化为空字符串，不同时持久化输入值；清空后同样保存空字符串。这样查看后直接保存不会把生成值误存成覆盖值。

## 开放接口

矩阵包查询接口在 `side_notes.value.frontend.value` 中暴露：

- `prodTrackingUrl`，description 为“生产环境埋点地址”
- `testTrackingUrl`，description 为“测试环境埋点地址”

查询结果遵循相同的值优先级，返回覆盖值或动态生成值。

开放写接口 `POST /api/open/matrix-packages/update-fields` 的 `sections.frontend` 增加上述两个文本字段。非空值作为覆盖值持久化；空字符串删除覆盖效果，使查询恢复动态生成值。现有未知字段校验和文本长度限制保持不变。

## 验证

- 无覆盖值时，Vimi 返回两条规则生成地址。
- 页面人工修改后，页面刷新和开放查询接口均返回修改值。
- 开放写接口写入后，页面和查询接口均返回写入值。
- 页面或接口写入空字符串后，恢复规则生成值。
- 包名或域名缺失时不生成不完整 URL。
- 现有 H5 字段行为不变。
